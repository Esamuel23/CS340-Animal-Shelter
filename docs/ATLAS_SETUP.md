# MongoDB Atlas Setup (do this yourself)

These steps move the database to a free Atlas cluster with least-privilege users and an IP allow
list. Everything else in the repo was built and tested against a local `mongod --auth` with the
same roles, so the code does not change — only the connection strings do.

Take a screenshot at each **[screenshot]** mark for the Milestone Four narrative. Atlas renames menu items now and
then; if a label differs, look for the closest match (for example "Database Access" may sit under
**Security → Database & Network Access**).

## 1. Create the free cluster

1. Sign in at https://cloud.mongodb.com and create (or open) a project, e.g. `cs499`.
2. **Create** a cluster → choose **Free (M0)** → any nearby region → name it `cs499-shelter`.
3. If Atlas offers to create a user and add your IP during this wizard, you can skip it — steps 2–4
   below do it properly. [screenshot]

## 2. Custom role for the app (least privilege)

1. **Database Access → Custom Roles → Add New Custom Role**. Name: `shelterApp`.
2. Add these collection actions, each scoped to database `aac` and the named collection:

   | Collection | Actions |
   |---|---|
   | `animals` | `find`, `insert`, `update`, `remove` |
   | `visits` | `find`, `insert` (only needed if you turn on the employer portal) |
   | `portal_sessions` | `find`, `insert`, `update`, `remove` (portal only) |

3. Do **not** add any database-wide or cluster actions. Save. (Free clusters can take ~30 seconds
   to apply role changes.) [screenshot]

## 3. Database users

1. **Database Access → Add New Database User** → Password authentication.
   - Username: `shelter_app`. Click **Autogenerate Secure Password** and copy it somewhere safe
     (a password manager — not a file in the repo).
   - Database User Privileges → **Custom Roles** → `shelterApp`. Nothing else. [screenshot]
2. Add a second user for setup scripts:
   - Username: `shelter_setup`, autogenerated password.
   - Privileges → **Specific Privileges** → `readWrite` on database `aac` and `dbAdmin` on database
     `aac`. (Not `readWriteAnyDatabase`, not `atlasAdmin`.) [screenshot]
   - This user is only used from your laptop to run `setup_db.py` and `explain_report.py`. The
     dashboard never uses it.

## 4. Network access: your IP only

1. **Network Access → IP Access List → Add IP Address → Add Current IP Address**. Add a comment
   like "Elijah laptop". [screenshot]
2. Do **not** add `0.0.0.0/0` ("allow access from anywhere").
3. If your home IP changes, connections will time out after 5 seconds with a "database is not
   reachable" message. Update the entry and try again. For a hosted deploy later, add only the
   host's outbound IP(s).

## 5. Connection strings into `.env`

1. Cluster → **Connect → Drivers → Python**. Copy the `mongodb+srv://...` string.
2. In the repo: `copy .env.example .env` (Windows) or `cp .env.example .env`.
3. Fill in, replacing `<password>` with each user's real password:

   ```
   MONGO_URI=mongodb+srv://shelter_app:<password>@<your-cluster-host>/?retryWrites=true&w=majority
   MONGO_SETUP_URI=mongodb+srv://shelter_setup:<password>@<your-cluster-host>/?retryWrites=true&w=majority
   MONGO_DB=aac
   MONGO_COLLECTION=animals
   ```

   Atlas users authenticate against `admin` by default, which is what the `+srv` string uses, so no
   `authSource` is needed here (the local setup used `authSource=aac` because the users were created
   in `aac`).
4. Check `.env` is ignored: `git status` must NOT list `.env`. [screenshot of `git status`, not of `.env`]

## 6. Load the data and build indexes

```bash
python scripts/setup_db.py
```

Expected: `created collection with validator`, `imported 9999 of 10000 rows; rejected 1`
(rec_num 8055, negative age — see `data/README.md`), then the index lines. Run it a second time to
show it is idempotent (`import skipped`). [screenshot both runs]

## 7. explain() evidence on Atlas

```bash
python scripts/explain_report.py
```

This drops and recreates the two indexes, so run it before you share the dashboard with anyone.
It rewrites `docs/explain/SUMMARY.md` with Atlas numbers. Docs-examined counts should match the
local run (9,999 → 17 / 5 / 4). Milliseconds will be noisier on a shared M0 — lead with docs
examined. [screenshot the table] If `$collStats` is refused on M0, the index-size table will be missing;
in that case use **Collections → aac.animals → Indexes** in the Atlas UI, which shows each index's
size, and screenshot that instead.

## 8. Prove least privilege on Atlas (optional but strong evidence)

```bash
python scripts/injection_demo.py
```

And in a Python shell with `MONGO_URI` (the app user), try `collection.drop()` — Atlas should
answer `not authorized`. [screenshot]

## 9. Run the dashboard against Atlas

```bash
python app.py
```

Open http://127.0.0.1:8050. [screenshot one rescue profile selected]

## If something fails

| Symptom | Likely cause |
|---|---|
| `MONGO_URI is not set` | `.env` missing or not in the repo root |
| "database is not reachable" after ~5 s | IP not on the access list, or cluster paused |
| "rejected the credentials" | wrong password or user created in a different project |
| "not allowed to do that" from setup_db.py | `MONGO_SETUP_URI` empty, so it fell back to the app user |
